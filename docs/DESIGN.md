# “EchoMemo” (回响笔记) —— 极简语音思维导图与日记

这是一个结合了 **Flutter** 极致交互体验与 **Python** 强大AI处理能力的“小而美”项目构思。旨在通过语音交互，帮助用户捕捉稍纵即逝的灵感与情绪。

## 1. 项目目标与核心功能

### 核心价值主张
**“释放双手，让思维自然流淌。”**
解决用户在移动端输入文字繁琐、灵感记录不及时、情绪记录难以坚持的痛点。它不仅仅是一个录音机，更是你的私人思维助理。

### 核心功能 (3-5个)
1.  **极速语音卡片 (Instant Voice Card):**
    *   用户只需按住一个悬浮按钮即可说话，松开即生成一张“语音卡片”。
    *   后台自动静默上传、转写（STT）并保存，无感知延迟。
2.  **AI 智能摘要与标签 (Smart Insight):**
    *   利用后端 LLM 对语音内容进行“一句话摘要”、自动提取关键词标签（如 #灵感、#焦虑、#会议）和情感分析。
3.  **情绪热力图 (Mood Heatmap):**
    *   根据语音语调及内容的情感分析，自动生成月度情绪色块图，直观展示心理状态变化。
4.  **时光流 (Time Flow):**
    *   以极其精美的极简时间轴展示卡片，支持按“标签”或“情绪颜色”筛选回顾。

### 如何实现“小而美”
*   **界面:** 摒弃复杂的菜单，主界面仅保留时间轴和录音按钮，采用“留白”设计。
*   **交互:** 强调手势操作（下滑搜索，左滑归档），配合流畅的 Hero 动画。
*   **专注:** 仅专注于“记录”与“回顾”，不加社交、不加广告。

## 2. 技术栈选择与理由

### 前端：Flutter
*   **理由:**
    *   **UI表现力:** 需要实现丝滑的录音波纹动画和时间轴滚动效果，Flutter 的 Skia 引擎优势明显。
    *   **跨平台:** 一套代码同时覆盖 iOS 和 Android，符合独立开发的高效要求。
    *   **插件生态:** `flutter_sound` 或 `record` 等音频库非常成熟。

### 后端：Python (FastAPI)
*   **理由:**
    *   **AI 生态:** Python 是 AI/ML 的首选。利用 `OpenAI` SDK 或 `Faster-Whisper` (本地部署) 处理音频转文字和摘要生成最为便捷。
    *   **性能:** FastAPI 基于 Starlette 和 Pydantic，拥有极高的性能（异步处理音频上传和 AI 推理），且自带 Swagger 文档，方便前后端联调。
    *   **开发效率:** 代码简洁，类型检查完善，适合快速迭代。

## 3. 前后端架构设想

### 前端 (Flutter)
*   **主要模块:**
    *   `RecorderModule`: 处理录音权限、文件流、波纹动画。
    *   `TimelineModule`: 展示卡片列表，支持无限滚动。
    *   `StatsModule`: 绘制情绪热力图（使用 `fl_chart` 或自定义 Painter）。
*   **交互流程:**
    *   用户按住 -> 录音开始 -> 松开 -> 本地先展示临时卡片 -> 后端返回结果后静默更新卡片内容。

### 后端 (Python FastAPI)
*   **API 设计:** RESTful API
    *   `POST /memo/upload`: 上传音频文件（异步任务）。
    *   `GET /memos`: 获取卡片列表（分页）。
    *   `GET /stats/mood`: 获取情绪数据。
*   **数据模型 (Entities):**
    *   `User`: 用户基本信息。
    *   `Memo`: 核心实体（字段: audio_url, transcription, summary, tags, mood_score, created_at）。
*   **数据库:**
    *   **PostgreSQL:** 推荐用于生产环境，支持 JSONB 存储灵活的 AI 分析结果。
    *   **SQLite:** 开发初期可用，配合 SQLAlchemy 或 Tortoise-ORM 方便切换。
*   **认证:** OAuth2 + JWT (JSON Web Tokens)。

### 数据交互
*   **API:** 使用 RESTful API 进行主要数据传输。
*   **实时性:** 可选 WebSocket 用于实时推送转写状态（“正在转写中...” -> “完成”）。

## 5. 潜在挑战与解决方案

1.  **挑战: STT (语音转文字) 的准确率与延迟**
    *   **对策:** 采用“乐观UI”策略，先上传录音并在前端显示“处理中”占位符。后端使用异步队列（Celery 或 FastAPI BackgroundTasks）处理耗时任务。优先使用 Whisper API (高精度) 或 部署 tiny 模型 (低成本)。
2.  **挑战: 隐私与数据安全**
    *   **对策:** 音频文件加密存储。提供“仅本地模式”选项（未来），即仅在本地保存音频，不上传云端（牺牲转写功能或使用端侧模型）。
3.  **挑战: 跨平台音频格式兼容性**
    *   **对策:** 统一转码。前端录制通用格式（如 AAC/M4A），后端接收后统一利用 `ffmpeg` 转为 WAV 输入给 AI 模型。

## 6. 可扩展性与未来展望

*   **多端同步:** 扩展 Web 端 (Flutter Web) 或桌面端，方便在电脑上整理笔记。
*   **知识图谱:** 当笔记积累多了之后，利用 AI 自动关联相似的笔记，形成用户的“第二大脑”知识网络。
*   **输出能力:** 支持一键将某段时间的语音笔记整理成一篇 Markdown 文章或周报。
